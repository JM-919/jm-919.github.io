2. 「加密打包」时到底发生了什么

① 打包时的网络行为：勾选「启用验证服务器」后，工具需要连通验证服务器/验证数据库<br>以取得产品标识、版本号与授权策略；连不上即报 无法连接验证服务器 / 无法连接Safengine服务器。<br>（这两条串都是给打包期和运行期共用的错误提示。）

② 嵌入内容：受保护程序内嵌授权配置 + RSA 公钥（授权选项 → RSA密钥长度 1024/…），<br>并有 SELicenseSDK.h 中的 SE_ERR_LICENSE_HARDWARE_ID_MISMATCH、SELicenseHashInfo.Hash[16]<br>等运行期校验结构。

③ 运行期的三条通道（LicenseDB/webfront/web/include/check.inc.php 明确给出 HTTP 契约）：

动作请求

返回格式固定：成功 (success) …，失败 (fail) …。

4. 判定与注意事项

  • .sedata 段加密是壳自身的保护，与「验证服务器地址」无关； 地址不需要脱壳，它就在明文的语言资源 DLL 里 —— 这也是本项目最省力的一步。
  • 字符串写的是「例如」：说明这是 Safengine 预置的托管服务示例值。 你若购买的是官方托管授权，就用它；若是自建，改为自己的地址。 同一份 Langs/*.dll 两处一致，可确认非笔误。
  • 端口 10001 上的协议为私有二进制协议（走 WS2_32）， 不要假设它是 HTTP；方案 B 必须先抓包再写应答。
  • GetHWID.exe 内嵌标题为 Safengine Licensor v2.4.0.0， Shielden.exe 内嵌 Safengine NetLicensor v2.4.0.0 —— 前者是离线机器码工具，后者是联网验证客户端。
  • 归档里所有 http(s):// 字符串（symcb.com / thawte.com / usertrust.com / crl.microsoft.com …） 都是代码签名时间戳与 CRL/OCSP，与授权验证无关，勿误判。

7. 插件体系与服务器验证的关系（Plugin.dll / PluginBin.dll）

结论先行：这两个 DLL 里没有任何服务器验证流程。 它们只在授权校验的前后挂勾子，<br>校验本身发生在壳里。

7.1 清单

文件位宽大小加壳角色

7.2 导出接口（8 个，与 2010 版 CHM 已不一致）

CHM 里写的 Initialize / PluginMain 已更名，以 PDK/PluginSDK.h 为准。

7.3 它们没有服务器验证：三重否定证据

检查结果
导入表无 WS2_32 / WININET / WINHTTP / URLMON / libmysql；全是 KERNEL32/USER32/GDI32/COMCTL32/ole32/… 这些纯 GUI 栈
字符串（网络/授权关键字全扫）零命中。唯一的 server 命中是 MFC 样板 LocalServer32/InProcServer32/XAccessibleServer
PluginBin.dll 的 SDK 导入只导入一个：SEGetAppStatus()

SEGetAppStatus() 返回 SE_STATUS_INIT / SE_STATUS_NORMAL（SESDK.h），<br>Splash 用它判断壳初始化是否完成，以便在正确时机显示启动画面 —— 与授权无关。

7.4 但它们确实挂在授权流水线上（这正是关键）

PDK/PluginSDK.h 定义插件类型位：

实测 Splash/Plugin.dll::GetPluginType() 的机器码：

0x6 = BEFORE_LICENSING | NO_PROTECT —— 即：Splash 在授权校验之前执行，<br>且自身不受保护。所以启动画面会在授权失败时照样显示。

DllBox/Plugin.dll::GetPluginType() 不是常量返回（cmp dword [0x1004a300],0; je …），<br>类型由 DllBox.ini 在运行时决定。

7.5 对我们目标（转本地验证）的含义

  1. 改插件不能绕过服务器验证 —— 验证逻辑不在插件里，在壳（受保护程序的 Safengine 运行时）里
  2. GET_LICENSE 插件理论上能拿到授权文件明文（pKeyBuf/dwKeySize）—— 这是观察授权结构的合法切入点，但 Splash/DllBox 都没用这个类型
  3. 插件引用的是 SESDKDummy.dll / SESDKDummy64.dll（45 / 42 个 SDK 导出）—— 真正实现在壳内，Dummy 只是链接期的桩。想知道授权怎么校验，得看壳，不是看插件
  4. 与 3306 / 10001 两条通道无关：插件不发任何网络请求
